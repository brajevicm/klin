# CI cost before and after #368

GitHub Actions bills each job in whole minutes, rounded up. All numbers
below come from `gh run list` and `gh run view` on `brajevicm/klin`.

## Before

The sample is the 20 most recent successful `quality` runs on pull requests,
2026-09-22 and 2026-09-23. Later runs failed on the Actions budget and hold no
timings.

| Step | Median | Range |
| --- | ---: | ---: |
| `quality` job | 328 s | 226 to 402 s |
| `cargo build --release --locked` | 113 s | 69 to 121 s |
| `cargo nextest run --locked` | 148 s | 109 to 158 s |
| `cargo clippy` | 44 s | 28 to 51 s |
| `./target/release/klin gate --strict` | 7 s | 4 to 8 s |
| `Release` plan job on a pull request | 24 s | 21 to 130 s |

A `quality` run bills 6 minutes. The `Release` run on a pull request bills 1
minute.

The cadence from 2026-09-16 to 2026-09-30 (15 days):

- 81 pull requests were opened. 77 of them merged.
- 70 merge commits reached `main`. 4 of them touched a release input.
- `quality` ran 209 times on pull requests and 91 times on pushes to `main`.
- `Release` ran 254 times on pull requests.

The run counts include the runs that failed on the Actions budget from
2026-09-29. Those runs started no steps, so they probably billed nothing. The
totals below are therefore the cost at this cadence when every run is billed
in full. Before and after use the same counts, so the reduction holds.

At full cost, pull requests use about 209 × 6 + 254 × 1 = 1,508 minutes,
which is 18.6 minutes for each pull request. Pushes to `main` use about
91 × 6 = 546 minutes.

## After

These numbers are estimates. CI fails on the Actions budget since 2026-09-30,
so no run of the new workflows exists yet. Replace them with measured values
after the first 20 runs.

- The release build step goes. That removes about 113 s.
- The gate runs on the debug binary that `cargo nextest run` already built.
  In a fresh target directory, `cargo build --locked` after
  `cargo nextest run --no-run` compiled no crate and took 0.04 s.
  On an M1 Pro with a fresh state directory, the debug gate took 29.6 s and
  the release gate took 7.6 s. At that ratio, the CI gate goes from 7 s to
  about 27 s.
- The estimated `quality` job is 328 − 113 − 7 + 27 ≈ 235 s. That bills 4
  minutes, or 5 minutes for a run near the top of the range.
- `quality` now runs on every push to a pull request, like `Release` did. That
  is about 254 runs in the same window. A newer push cancels an older run, so
  the real count may be lower.
- `dist plan` runs only on the pull requests that touch a release input. That
  was 4 of 70 merges (about 6%), so about 15 runs of 1 minute.

| | Before | After, 4-minute runs | After, 5-minute runs |
| --- | ---: | ---: | ---: |
| Minutes for each pull request | 18.6 | 12.7 | 15.9 |
| Pull request minutes in 15 days | 1,508 | 1,031 | 1,285 |
| Reduction | | 32% | 15% |

Pushes to `main` now run `quality` every time. That is at most 115 runs in
the same window, instead of 91. At 4 minutes each, that is 460 minutes
instead of 546.
