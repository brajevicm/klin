# CI cost before and after #368

GitHub Actions bills each job in whole minutes, rounded up. All numbers
below come from `gh run list` and `gh run view` on `brajevicm/klin`.

## Before

The sample is the 20 most recent successful `quality` runs on pull requests,
2026-09-22 and 2026-09-23. Later runs failed on the Actions budget and hold no
timings.

| Step | Median | Range |
| --- | ---: | ---: |
| `quality` job | 328 s | 226 to 402 s |
| `cargo build --release --locked` | 113 s | 69 to 121 s |
| `cargo nextest run --locked` | 148 s | 109 to 158 s |
| `cargo clippy` | 44 s | 28 to 51 s |
| `./target/release/klin gate --strict` | 7 s | 4 to 8 s |
| `Release` plan job on a pull request | 24 s | 21 to 130 s |

A `quality` run bills 6 minutes. The `Release` run on a pull request bills 1
minute.

The cadence from 2026-09-16 to 2026-09-30 (15 days):

- 81 pull requests were opened. 77 of them merged.
- 70 merge commits reached `main`. 4 of them touched a release input.
- `quality` ran 209 times on pull requests and 91 times on pushes to `main`.
- `Release` ran 254 times on pull requests.

The run counts include the runs that failed on the Actions budget from
2026-09-29. Those runs started no steps, so they probably billed nothing. The
totals below are therefore the cost at this cadence when every run is billed
in full. Before and after use the same counts, so the reduction holds.

At full cost, pull requests use about 209 × 6 + 254 × 1 = 1,508 minutes,
which is 18.6 minutes for each pull request. Pushes to `main` use about
91 × 6 = 546 minutes.

## After

The sample is 3 attempts of `quality` run 36752827135, the push of the #368
merge to `main`, on 2026-09-30. A push run and a pull request run execute the
same job. The run timing API reports 0 billable milliseconds for old and new
runs alike, so the billed minutes below come from the job time, rounded up.

| Step | Median | Range |
| --- | ---: | ---: |
| `quality` job | 285 s | 261 to 302 s |
| `cargo nextest run --locked` | 182 s | 162 to 195 s |
| `cargo clippy` | 46 s | 42 to 48 s |
| `cargo build --locked` | 0 s | 0 s |
| `./target/debug/klin gate --strict` | 43 s | 30 to 43 s |

A `quality` run bills 5 minutes. The attempt of 302 s billed 6.

#368 changed the job by about 77 s: the release build (113 s) and the release
gate (7 s) went, and the debug gate (43 s) came. The debug gate is slower than
the estimate of 27 s from the local ratio.

The job fell by only 43 s, from 328 s to 285 s, because the test suite grew
between the two samples. The nextest median rose from 148 s to 182 s. With the
release build of 2026-09-23, the old workflow over today's tests takes about
285 + 77 = 362 s, which bills 7 minutes. The release build most likely grew
too, so that figure is a lower bound.

`release-plan.yml` has not run yet. Its estimate is 1 minute, from the median
of 24 s for the old `Release` plan job.

At the cadence of 2026-09-16 to 2026-09-30, with every run billed in full:

| | Before, tests of 09-23 | Before, today's tests | After |
| --- | ---: | ---: | ---: |
| Minutes for one `quality` run | 6 | 7 | 5 |
| Pull request minutes in 15 days | 1,508 | 1,717 | 1,285 |
| Minutes for each pull request | 18.6 | 21.2 | 15.9 |
| Push minutes on `main` in 15 days | 546 | 637 | 575 |
| All minutes in 15 days | 2,054 | 2,354 | 1,860 |

After #368, `quality` runs on 254 pull request pushes instead of 209, and on
at most 115 pushes to `main` instead of 91, because no path filter skips it.
A newer push cancels an older run, so the real counts may be lower.
`dist plan` runs about 15 times instead of 254.

Against the same tests, pull requests use 25% fewer minutes and all of CI uses
21% fewer. Against the sample of 2026-09-23, the reductions are 15% and 9%.
