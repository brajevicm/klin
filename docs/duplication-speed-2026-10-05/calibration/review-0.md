The decisions distinguish actionable repeated behavior (regex binding/replacement, SMTP construction, cache invalidation, expression rewriting, filesystem validation and rule-action mapping) from dependency imports, typed adapters and protocol/schema declarations. Operation or platform differences alone did not excuse an identical behavior kernel. Conversely, common signatures around different operations were not labeled copy merely because tokens matched.

The generated label is supported by the [Thrift compiler header](https://github.com/glaredb/glaredb/blob/8001afa4cff0cecfec79f2cb292108da08aa4c35/crates/ext_parquet/src/format.rs#L2). Documentation sidebar matches are conservatively `required-shape`, not automatically generated: [the current generation command](https://github.com/karakeep-app/karakeep/blob/f8ae986692f82efe8c1f3940907aab553e4f5a49/docs/package.json#L16) establishes current API documentation generation but does not prove how every archived sidebar was produced.

Uncertainty is explicit: fast-path execution/reduction copies require preserving and measuring optimized branches if a helper is extracted. One overlapping Dialog candidate is `distinct`, because it does not establish two independent copies. Decimal multiply shares only adapter setup with add/sub, while add/sub share an actionable binder kernel; these pairs receive different labels. `mixed` is reserved for a family with both copy and independent members, following issue #480, rather than used as an uncertainty bucket. Source review establishes repeated implementation, not whether deleting a copy is safe without tests and measurement.
